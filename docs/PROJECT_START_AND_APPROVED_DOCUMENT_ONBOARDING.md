# Project start choices and approved-document onboarding

Clicking **New project** or **Start a project** first presents two tiles:

1. **Start from scratch with the client requirement** opens the creation form with Current SDLC stage locked to Planning and optional metadata. The creation request always uses Planning, including after switching from the approved-document path. Later workspace stage navigation is unchanged.
2. **I have some requirements already approved** opens a creation form with artifact checkboxes grouped by SDLC stage and Draft/Approved radio options beside each document. Draft is selected by default; status options become editable when the document is selected.

The supported stage/artifact checklist is Planning (BRD), Analysis (FRD and User Stories), Design (TDD), Development (ABAP), and Testing (SIT, UAT and Audit Report). At least one artifact is required for the second path. The shared approval declaration checkbox has been removed: selecting Approved is the user's offline approval declaration for that document only. Project name, starting draft stage, optional requirement and optional metadata remain available.

Both creation forms have a small back arrow beside the heading to return to the two start options without losing entered values. Client name appears directly below Project name in both forms. It is optional, stored as a separate project field (up to 150 characters), and shown on the compact cards in Your projects when present. Existing projects without a client name remain readable. Creation retries include a supplied client name in their identity check; requests without it retain the existing signature format. Stage assistance remains available on the approved-document path.

After creation, CoWork posts the first document request into the project conversation and displays a one-document upload control in chat, with the chosen Draft/Approved status. Each successful import advances to the next selected artifact in SDLC order. The selected list and per-document statuses (`import_artifact_statuses`) persist on Project. Draft selections are complete when their artifact is registered; Approved selections require recorded approval. Reopening/restarting retains progress and statuses. Empty or unreadable artifacts do not advance the queue. Upload errors remain visible and can be retried. Existing import plans and API callers that omit the status map retain the earlier all-approved behavior; the new UI always sends explicit statuses for selected documents.

Draft imports remain Draft without an approval event. For documents marked Approved, import records the user's per-document offline approval declaration using the existing authenticated approval service, rather than implying that CoWork independently certified the contents. Original documents, extracted/aligned artifact versions and normal approval audit records remain available through Files and Project Status. Development and Testing completion are not inferred from document imports: their existing explicit confirmations still apply.

The new protected POST `/api/projects/{project_id}/onboarding/upload` uses the existing upload and approval mutation contracts with separate durable child request IDs. Identical retries do not create another artifact; an interruption between upload and approval can resume. Changed content with the same ID conflicts. Explicit stale revisions are rejected. Existing projects default to no import plan and retain their current behavior. The parent/task LangGraph runtime and public chat API remain unchanged.

Assumptions: this feature uses the five stages currently supported by V1.1. Approval is the authenticated user's offline declaration. Document parsing retains existing supported formats and the 10 MB limit. No new Deployment/Maintenance automation or external approval verification is introduced.
