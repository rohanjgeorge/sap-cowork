# Chat stage guidance and sequential clarifications

Updated 3 November 2026.

The workspace top bar labels the stage selector **Work on:** and the approved-stage badge **Current Stage:**. The selector still represents `current_draft_stage`, while the badge still represents `current_approved_stage`. Domain field names, progression rules and API contracts are preserved. The old `Generate ...` task subtitle beneath the project name is no longer shown.

Selecting a stage commits the existing revision-checked navigation operation, then requests a short contextual response through the configured ModelGateway and the existing non-checkpointed LangGraph conversation path. The model is asked to discuss requirements, existing documents and unresolved inputs, asking at most one focused question if needed. This does not start artifact generation or advance Approved Stage. The deterministic demo provider identifies itself explicitly; tests do not make paid model calls.

Stage guidance uses a copied conversation state and leaves active generation identity and checkpoint waits intact. Navigation guidance remains available while a task is blocked on clarification. It retains active-project, source authorization, context-correlation and response-validation checks, while generation blockers continue to apply to artifact-producing actions. A provider failure is surfaced without replacing the reply with a generic `Generate ...` recommendation; the selected stage remains committed. Successful navigation retries replay their recorded response without another model call.

Clarifications remain persisted in ProjectState with IDs, task links, questions, answers, statuses and timestamps. All pending questions remain available in state/status and the existing API `questions` array. Chat presents only the first open question for the active task, and its composer submits that specific question ID. The assistant message also contains just the next question, rather than joining the entire list. Questions associated with other tasks are excluded from the current chat question and from the active task's remaining-question response.

After each answer, the next saved question is presented. Artifact generation remains paused until all questions for that task are resolved, then resumes the original task/checkpoint. Reopening and request replay preserve this behavior. Existing conversation history is retained.

Clarification submission now shows an immediate **Processing your answer…** live status immediately above the composer, independent of whether the backend has emitted its first progress event. The send button shows a spinner, and available progress events add short phase descriptions. The submitted answer stays readable in the input, which is read-only while that answer is processing. The input clears when the server removes the answered question from its open queue; failed requests retain editable answer text. The existing Retry request operation keeps its original request identity. Spinner animation respects reduced-motion preferences. Backend mutation, checkpoint, response-stream and provider behavior are unchanged.

Context categories such as SDLC and Business now appear inside the Context details, with a visible up/down chevron and an accessible expanded/collapsed state on the Context button. The clarification box uses reduced padding and paragraph spacing while keeping the complete question and continuation guidance visible.

Project Status replaces its introductory subtitle with clickable Clarifications, Decisions and Flags totals. These read the full records already returned in workspace ProjectState, including resolved clarifications/flags. Each total opens a read-only list in the rail with record statuses, saved clarification answers and a back arrow. Returning restores focus to the selected total, and lifecycle/approval/generation behavior is unchanged. Older responses fall back to their available clarification/flag summaries. No backend API changes are required for these displays.

The Project Status stage summary now reads **Working on:** and **Current Stage:**. Its compact task summary displays the saved current task, expected next artifact and recommended next action; the expected artifact is passed directly from workspace ProjectState, rather than assuming the default for the selected stage. Null values are labeled explicitly. The old duplicate recommended-action footer is removed. Stage navigation uses a compact two-column grid of rectangular buttons, retaining all five stages, backend colors, selection state and the Next marker. Full stage-status descriptions remain available in accessible names and tooltips. The top-bar Current Stage label also uses a colon consistently.

Coverage includes configured-provider requests and failure handling, no implicit artifact generation, durable navigation replay, unchanged clarification checkpoints during stage guidance, multi-question persistence across runtime recreation, answer-to-question correlation, no early generation, legacy clarification records, and snapshot/navigation safeguards. The browser suite covers stage-specific demo guidance and unchanged Current Stage: STO remains the final release gate. Actual release results are recorded in `TEST_RESULTS.json`.
